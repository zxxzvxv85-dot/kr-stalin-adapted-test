# 陆军兵器设计总局

来源：`tools/design/ordnance_design_bureau/陆军兵器设计总局.drawio`，机制数值来源包括该图内嵌的五张截图。批准数值与连线在同目录`spec.json`。当前只实现这一家陆军兵器MIO，装甲车辆总局未实现。

## 入口与状态

- `RUS_future_foreign_030`“整合地方党组织”奖励调用`RUS_odb_unlock`；MIO仅在完成此国策后可见、可用。首次初始化用MIO旗标去重，不重置已培养的次数。
- MIO为`RUS_odb_organisation`。17个可见槽位、7列5行，实际数据库48个特质定义；末行10/10/10/5个定义同位逐次显示，最后一次保留为已完成。每次消耗一个原生特质点，没有额外的后几档等级门槛。多个连入前置均为AND；新型火炮研发与开发土地、扩大试验性装备测试与产线通用化分别互斥。测试到通用化的横线是互斥，不是前置；通用化只需伊热夫斯克与模块化两项。
- 五家原厂只在原`available`条件中追加对应`RUS_odb_merged_*`国家旗标检查。其余原厂树定义完整保留。合并时先记录原厂等级、经费，再按原生`add_mio_size`/`add_mio_funds`转入并扣除原厂经费；旗标确保只转移一次。只继承图定加成与机制，不复制旧特质。已有装备设计仍按引擎的原有MIO绑定规则处理；本实现不强行改装库存装备。
- 授勋沿用原`RUS_TOZ_Medals`三项决议/任务，不重建已有自动任务；保留国家`TOZ_Divisions`、`TOZ_Required_Funds`，只有缺失时才采用原版4/500。整合后统一从总局支付；每次7支仍为7支。原始授勋函数只在整合标记存在时分派至新效果，非整合分支与KR原AST一致。
- 新勋章使用11种静态勋章定义，四项从10%逐档+0.5个百分点至15%；只决定新授勋章的等级，不修改旧勋章。原版组织度限制、组织度消耗和累计计数保留。
- 每周生产经费达到8.96（每日1.28）且至少一条生产线时增加6%研究加成，含机构修正的最终加成封顶125%；取消研究重置，整合布良斯克后完成研究保留。转入经费、投资支出、授勋支出和直接发放总局的补助调整周基线，避免被当作新增生产收入。
- 两项KR原研发方针现允许总局使用：`RUS_mio_policy_RD_Cap`提高研究软上限25个百分点（125%→150%），`RUS_mio_policy_RD_Growth`提高周增长1个百分点（6%→7%），两者均经费获取-5%。生成器从KR原`RUS_policies.txt`仅扩充两项允许名单，其余AST完整保留，继承25政治点/180天默认冷却。总局在首次解锁初始化`max_research_speed`/`weekly_research_speed_gain`，周结算读取变量，提示用独立临时变量，不能再用固定值覆盖。方针可先于模块化选择，后续节点及重复初始化不重置它；取消研究保留方针参数。原生policy文档规定allowed仅在开局评估，新资格需要新档，不添加存档迁移。
- 奥布霍夫每30次每日脉冲向一个可用且参与任务的MIO发放100–300经费，不因多条生产线叠加。投资严格要求经费>1000；10档隐藏精神逐档替换，生活消费品期望累计至+10%。开发土地分支的5档隐藏精神提供全国地区最大工厂数累计+5（也作用于以后取得的地区），每档总局升级需求+5%。

效果格式参考本机KR及2946487287简体汉化：

- KR `01_American Civil War effects.txt`的`USA_mio_merger_effect`及`USA_MIO_funds_and_level_merger_tt`：规模/经费转移用原生效果；原厂停用只留必要自定义说明。
- KR `RUS_organization.txt`的TSTZ同位重复、BMZ研究保留、原TOZ授勋；原`KR_medals.txt`四项部队修正。
- KR `RUS_MIO_Research_Gain_tt`：周增长、上限、每日门槛、当前经费的标准参数化提示。独立状态函数使用实际>=门槛，避免严格大于时的边界误显示。
- 隐藏精神用`show_ideas_tooltip`原生展示净增一档修正，执行放在`hidden_effect`；勋章升级用KR的四项modifier tooltip，只把原生无法表示的新授范围及剩余培养次数放在自定义提示。

预览左侧展示一个特质的标准条件/效果，不包含格子尺寸等制作信息。图像为脚本布局预览，不是游戏截图。完整美术来源保留为`ordnance_bureau_master.png`，游戏导出64×64；使用前次内置ImageGen产出的去圆规图，本轮没有重新生成图片。

五家整合企业节点使用私有`GFX_RUS_odb_trait_*`。KR企业标志原图为64像素左右，原生特质框不会自动缩小，不能直接引用`GFX_idea_*`。`export_ordnance_trait_icons.py --write`从KR只读原图导出48×48透明画布（主体最大32×32）、私有图元和`trait_icons.json`来源/SHA清单；默认或`--check`只校验、不绘图。企业列表原图元不变。注意原生trait_icon的(-21,-32)不是画布尺寸：原版reliability与KR研究速度图标实际都为48×48，中心是(3,-8)，与框(-29,-40)+内圆(32,32)一致。曾误用42×42导致向左上各偏3像素，20261019已修正并新增真实PNG尺寸与中心一致性校验。五项用原生第三帧及BMZ放大图核对中心；预览绘图器自动缩放不能代替这个检查。图元ID和纹理路径保持不变，此次纯位置修正可以继续当前存档。

## 维护与验证

默认/`--check`只读；`--write`生成专用运行文件并对四份共享文件做局部、幂等适配。开局生成器会从KR重建`RUS effects (Russia).txt`，因此其`render_native_anger`必须继续调用本生成器的`patch_legacy_effects`，不得丢失授勋分派。原开局回归核对新授勋分支和原生else的完整AST。

```powershell
python tools/generate_ordnance_design_bureau.py --check
python tools/export_ordnance_trait_icons.py --check
python tools/validate.py --group mio opening
python tools/check_runtime_structure.py
python tools/render_ordnance_design_bureau.py
```

专项模型执行实际脚本中的五家移交、人数7/费用350/剩余任务6天、缺失基础值、合并前后支付、AND/互斥、连续培养和上限、1000/1001支出边界、周学习/取消/完成、30日补助等分支，并比较原厂其他字段与任务开始前Git基线。模型不模拟引擎的全部等级阈值或装备重绑定。
